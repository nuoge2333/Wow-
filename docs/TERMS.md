# 📖 术语解释

> 面向非专业用户，用通俗语言解释本项目涉及的核心概念。
> 不要害怕这些名词，每一个极客都是从看懂这些词开始的。

> 📌 **命令引导词说明**：文档中写的 `wow xxx` 是命令简写。**Linux / macOS** 实际要输入 `./wow.sh xxx`（比如 `./wow.sh server start`）；**Windows** 实际要输入 `wow.bat xxx`（比如 `wow.bat server start`）。后文所有命令同理，不再重复说明。

---

## 一、基础概念

### CLI (Command Line Interface)
**命令行界面**。就是那种黑色背景、白色文字的窗口（Windows 叫 CMD/PowerShell，Mac/Linux 叫终端）。你在这里输入命令，电脑执行操作。

**在 wow 中：** 输入 `wow server start` 来启动服务器。M 模式其实就是把 CLI 封装成了数字菜单，方便你按数字选择。

---

### Web 面板
**浏览器里的管理页面**，有按钮、图表、输入框，点点鼠标就能操作。

**在 wow 中：** 运行 `wow web start` 后，在浏览器打开 `http://localhost:8080`，就能看到图形化的管理界面。

---

### 方案 (Scheme)
**一个完整的 Minecraft 服务器实例**（你可以直接把它当成“一个独立的世界”）。它包含了核心、模组、插件、存档、配置、日志等所有文件。

**在 wow 中：** 你可以创建多个方案（如“生存服”、“创造服”），每个方案相互独立。wow 独创的机制让多个方案可以共享底层文件，不仅省硬盘，切服还极快。

---

### 方案模式 (Scheme Mode)
**wow 的核心架构**。以前的启动器开 3 个服要占 3 份硬盘，而 wow 让它们共享相同的核心和模组。

**原理：**
- 重复的文件（如同一个核心、同一个模组）只存一份在 `pool` 里。
- 你切到哪个方案，wow 就自动把需要的文件“借”过来补齐。
- 切换走时，自动瘦身，把能共享的文件还回去。

---

### 资源池 (Pool)
**存放共享文件的公共仓库**，位于 `core/pool/` 目录。里面存放了 `cores/`（核心）、`mods/`（模组）、`plugins/`（插件）。

wow 怎么知道两个文件一模一样？靠的是 **SHA-256**（见下方）。只要文件指纹一样，它就只存一份，大家共用。这是 wow 能省下大量硬盘空间的核心魔法。

---

### 方案状态 (minimal / partial / full)

| 状态 | 含义 | 比喻 |
|------|------|------|
| **minimal** | 所有资源都在 pool 中，方案目录只有配置和存档 | “空壳子”，只有自己的数据，工具在公共仓库 |
| **partial** | 部分资源在方案目录，部分在 pool 中 | “半成品”，部分工具自己带着，部分去仓库借 |
| **full** | 所有资源都在方案目录中 | “完整包”，所有东西都在自己手里，随时能跑 |

---

### 配置文件 (Config / YAML)
**告诉程序“怎么运行”的文本文件**。YAML 是一种常见配置格式，靠缩进表示层级，通常以 `.yaml` 或 `.yml` 结尾。

**在 wow 中：** 主配置常见为 `wow.yaml`，方案配置、面板配置也多为 YAML。改配置时注意缩进和冒号后的空格，改错可能导致启动失败。

---

## 二、wow 底层机制（开智区）

### SHA-256
**文件的“身份证号”（哈希值）**。无论文件多大，算出来的指纹永远是固定长度。哪怕文件里只有一个字节不同，指纹也会完全不一样。

**在 wow 中：** wow 用 SHA-256 来判断两个模组是否完全一样。一样，就只存一份在 pool 里，从而实现多方案共享，极大节省硬盘空间。

---

### pull (拉取) / prune (瘦身)
**pull**：从 pool 复制资源到方案目录，把服务器“补齐”到能启动的状态。
**prune**：把方案目录里与 pool 重复的文件删掉，改成共享引用，给硬盘“瘦身”。

**在 wow 中：** 默认由 `auto_scheme` 在切换方案时自动完成，一般不用手动敲。

---

### auto_scheme (自动方案管理)
**一个开关**，控制 wow 是否在切换方案时自动帮你拉取和瘦身。
- `true`（默认）：全自动，省心。
- `false`：手动管理，你切方案时 wow 不碰你的文件。

**设置：** `wow set auto_scheme false`

---

## 三、网络基础（联机必看）

### IP 地址
**电脑在网络里的门牌号**。分为内网 IP（比如 `192.168.x.x`，家里局域网用）和公网 IP（互联网上唯一的地址）。

**特殊 IP 速查：**
- `127.0.0.1`：本机环回地址，永远指向你自己。相当于“我自己”。
- `0.0.0.0`：监听所有网卡。相当于“来者不拒”。**在 wow 中绑定这个 IP，意味着允许局域网/公网访问面板。**

---

### localhost
**本机的别名**。通常等价于 `127.0.0.1`，表示“这台电脑自己”。

**在 wow 中：** 浏览器访问 `http://localhost:8080`，就是访问你自己电脑上的 Web 面板。朋友要从外面访问，就不能发 `localhost`，要发你的局域网 IP、公网 IP 或内网穿透链接。

---

### NAT (网络地址转换)
**小区保安兼收发室**。家里有十几台设备，但运营商只给你一个公网 IP。路由器（NAT）负责把你们的内网 IP 转换成公网 IP 去上网，外面的人想连进来，必须经过保安室做映射。

**为什么需要内网穿透？** 因为绝大部分人没有公网 IP，外面的朋友根本连不进你的服务器。

---

### Tunnel / 内网穿透
**一种“打洞”技术**。在没有公网 IP 的情况下，强行建立一条外网能访问到你本地网络的安全隧道。

**在 wow 中：** 执行 `wow web start --tunnel`，wow 会借助 Cloudflare 给你生成一个临时的公网链接，发给朋友直接就能进。

---

### 端口 (Port)
**电脑上不同程序的“门牌号”**。一台电脑可以跑很多服务（网页、游戏、数据库），IP 决定是哪台电脑，端口决定是哪个服务。

**在 wow 中：** Minecraft 服务器默认走 `25565` 端口，Web 面板默认走 `8080` 端口。如果端口冲突，服务器会报错起不来。

---

### 端口冲突 (Port Conflict)
**两个程序抢同一个端口**。比如你开了两个 Web 面板都想用 `8080`，后启动的那个就会失败。

**处理思路：** 关掉占用端口的旧程序，或给新服务换一个端口。看报错日志里出现 `EADDRINUSE` 时，通常就是端口被占了。

---

### 防火墙 (Firewall)
**系统或路由器里的“门卫”**，负责拦截或放行网络流量。

**在 wow 中：** 朋友连不进来，常见原因是防火墙没放行 `25565` 端口；外部打不开 Web 面板，也可能是 `8080` 端口没放行。先确认本机能访问，再查防火墙和路由器。

---

### 端口映射 (Port Forwarding)
**在路由器里做“转接”**：把公网 IP 的某个端口，转发到你内网某台电脑的某个端口。

**注意：** 端口映射的前提是你有公网 IP。没有公网 IP 时，端口映射也救不了，需要内网穿透。

---

## 四、运行环境

### JRE / Java
**运行 Minecraft 服务器必须的环境**。Minecraft 是用 Java 写的，没它跑不起来。

**在 wow 中：** 如果系统没装 Java，wow 会自动下载对应版本的便携 JRE，完全不需要你手动去折腾环境变量。

---

### JVM (Java 虚拟机)
**运行 Java 程序的“虚拟电脑”**。你平时听到的“分配 4G 内存”，其实就是给这台“虚拟电脑”分配内存。

**在 wow 中：** 启动时用 `--memory 4G`，就是在告诉 JVM 你可以用 4G 内存。太小会卡，太大可能导致系统崩溃。

---

### Node.js
**运行 wow 工具本身的底层环境**。wow 的后端是用 JavaScript 写的，没它跑不了 wow。

**在 wow 中：** 首次运行启动脚本时，会自动下载便携版 Node.js。

---

### 启动脚本 (Start Script)
**用来启动 wow 的入口文件**。Windows 下通常是 `wow.bat`，Linux / macOS 下通常是 `wow.sh`。

**在 wow 中：** 启动脚本会帮你检查环境、准备便携运行时，再把命令转交给 wow 主程序。你不需要手动配环境变量，按文档运行即可。

---

### 进程 (Process) / PID
**程序跑起来后，系统会给它一个编号，叫 PID（Process ID）**。关闭服务器，本质上就是结束对应的进程。

**在 wow 中：** 优先用 `wow server stop` 正常关服，让服务器保存存档。不要一上来就强杀 Java 进程，否则可能丢存档或损坏世界。

---

### 日志 (Log)
**程序运行过程的“流水账”**。启动失败、模组报错、玩家掉线、端口冲突，都会在日志里留下线索。

**在 wow 中：** 出问题先看日志最后几十行。方案目录和 `logs/` 目录下通常能找到服务器日志；Web 面板里也可能直接查看。

---

### TPS (Ticks Per Second)
**Minecraft 服务器每秒执行多少“刻”**。正常满值是 20。TPS 长期低于 20，说明服务器在卡顿。

**在 wow 中：** 看 TPS 比只看 CPU 占用更直观。TPS 掉到十几甚至个位数时，优先查模组冲突、内存不足、区块加载过重等问题。

---

### EULA (最终用户许可协议)
**Mojang 官方的用户协议**。服务端启动前，必须同意该协议（`eula=true`），否则直接闪退。

**在 wow 中：** wow 会帮你自动生成并同意，省去你去找文件的麻烦。

---

### 白名单 (Whitelist)
**服务器的“VIP 准入名单”**。开启后，只有名单里的玩家才能进入，防熊孩子必备。

**在 wow 中：** 用 `wow config white add 玩家名`，或者在 Web 面板里点两下搞定。

---

### SMTP
**发邮件的协议**。用于发送登录验证码、崩溃报告等。

**在 wow 中：** 在 `wow.yaml` 里配置好 SMTP 后，才可以使用邮件登录功能。

---

### authlib-injector
**外置登录注入器**。让 Minecraft 服务器支持第三方认证（如 LittleSkin）的工具。

**在 wow 中：** 配好 `auth.enable` 和认证地址，启动时 wow 会自动把它注入进去，让盗版/第三方账号也能验证登录。

---

## 五、Minecraft 相关

### 模组加载器 (Mod Loader)
**让 Minecraft 加载模组的框架**。不同模组需要不同的加载器。

| 加载器 | 说明 |
|--------|------|
| **Forge** | 最成熟的模组加载器，老牌模组数量最多 |
| **Fabric** | 轻量级，更新极快，现代模组首选 |
| **NeoForge** | Forge 的分支，高版本（1.20.1+）的新趋势 |
| **Quilt** | Fabric 的分支，兼容 Fabric 模组 |

---

### 模组 (Mod)
**修改或扩展 Minecraft 内容的文件**，比如新增物品、方块、生物、机制。模组通常需要玩家客户端和服务器同时安装同一套，否则可能进不去或报错。

**与插件的区别：** 模组偏“改游戏内容”，插件偏“管服务器功能”。模组通常两端都要装，插件通常只装服务器端。

---

### 插件 (Plugin)
**为服务器添加功能的扩展**，不需要玩家安装，直接在服务器端运行。

**与模组的区别：**
- 模组：需要玩家和服务器同时安装，否则进不去。
- 插件：只需服务器安装，玩家直接进，适合做小游戏、防熊、聊天管理。

---

### 服务端核心 (Server Core)
**真正运行 Minecraft 世界的 Java 程序**，比如原版、Paper、Forge、Fabric、Mohist 等。方案里说的“核心”就是它。

**在 wow 中：** 核心决定这个方案支持哪个游戏版本、支持模组还是插件、能不能混合。资源池里的 `cores/` 就是存放共享核心的地方。

---

### 混合核心 (Hybrid Core)
**同时支持模组和插件的服务端核心**（比如 Mohist、CatServer、Arclight）。

---

| 缩写 | 全称 | 说明 |
|------|------|------|
| CLI | Command Line Interface | 命令行界面 |
| JRE | Java Runtime Environment | Java 运行环境 |
| JVM | Java Virtual Machine | Java 虚拟机（分配内存就是给它） |
| SMTP | Simple Mail Transfer Protocol | 邮件发送协议 |
| PID | Process ID | 进程编号（用来杀后台的） |
| TPS | Ticks Per Second | 每秒刻数（衡量服务器卡不卡，20为满值） |
| EULA | End User License Agreement | 最终用户许可协议 |
| NAT | Network Address Translation | 网络地址转换 |
| IP | Internet Protocol | 网络协议/门牌号 |

| WAN | Wide Area Network | 广域网，通常指互联网 |

| API | Application Programming Interface | 程序之间对接的接口，wow 内部/面板会用到 |
