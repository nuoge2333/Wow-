## 一、测试目的

验证 wow 集成的陶瓦（Terracotta）联机功能，在真实网络环境下是否能够成功建立 Minecraft 服务器连接。具体验证以下三点：

1. wow 的 `lan host` 能否成功开房并生成房间号
2. 另一台设备能否通过房间号成功连接
3. 在真实网络环境下，连接是否稳定

## 三、测试流程

### 3.1 服务端启动

1. 在 Windows 10 上启动 Wow~ V3.5.6-26.2d
2. 执行 `wow server start`，启动 Vanilla 1.16 服务端
3. 服务端成功启动，日志输出 `Done (13.587s)! For help, type "help"`

### 3.2 陶瓦开房

1. 切换 wow 视图，执行 `lan host`，启动陶瓦联机
2. 陶瓦扫描本地端口，返回 `host-ok`
3. 成功生成房间号：`U/GB30-YMAT-NBN0-GXP1`
4. 服务端日志显示陶瓦成功注册房间

### 3.3 客户端连接

**客户端 1（SB）**：

- 在 Android 设备上打开 FCL
- 选择「加入陶瓦房间」
- 输入房间号 `U/GB30-YMAT-NBN0-GXP1`
- 成功连接，日志显示 `SB joined the game`

**客户端 2（nuoge）**：

- 在 Android 设备上打开 FCL
- 选择「加入陶瓦房间」
- 输入房间号 `U/GB30-YMAT-NBN0-GXP1`
- 成功连接，日志显示 `nuoge joined the game`

### 4.2 连接稳定性

- **客户端 2（nuoge）**：局域网内部连接，延迟极低，无卡顿。

### 4.3 流量连接测试

在测试过程中，进行了以下额外测试：

| 测试项 | 结果 | 原因分析 |
|--------|------|----------|
| 关闭 Wi-Fi 切换为流量 | ❌ 失败 | 移动网络 NAT 类型限制，P2P 打洞失败 |
| 切换回 Wi-Fi | ✅ 成功 | 恢复正常连接 |

**分析**：手机流量的 NAT 类型通常为对称型 NAT，P2P 打洞在没有中继的情况下必然失败。这是陶瓦底层 EasyTier 组网的已知限制，非 wow 代码问题。Wi-Fi ↔ 家宽可以成功，是因为家宽通常是全锥型或限制锥型 NAT，打洞成功率高。

## 六、技术分析

### 6.1 成功原因

1. **陶瓦组网机制**：陶瓦基于 EasyTier 实现 P2P 组网，在双方均为家宽的情况下，打洞成功率高，连接稳定。
2. **wow 集成流程**：`wow lan host` 成功完成陶瓦启动、端口扫描、房间注册、房间号生成全流程。
3. **跨平台兼容**：Windows 服务端 + Android 客户端组合验证成功。

### 6.2 已知限制

1. **移动网络 P2P 打洞失败**：手机流量 NAT 类型限制，无法与家宽建立 P2P 连接。这是 EasyTier 的已知限制，非 wow 代码问题。
2. **Android 服务端不可用**：此前已确认，Android 沙箱限制导致 Termux 无法对外暴露端口，本次测试中服务端使用 Windows 是正确选择。详见 [Android 已知限制说明](ANDROID_LIMITATIONS.md)。

在测试中，当客户端断开 Wi-Fi 切换为移动数据（4G/5G）时，连接立即超时失败。这并非 Wow 或陶瓦的 Bug，而是由运营商网络底层的架构决定的。

在 IPv4 时代，为了应对 IP 地址枯竭，运营商在移动数据网络上普遍部署了 CGNAT（运营商级 NAT）。这意味着成百上千个手机用户其实共用同一个公网 IPv4 地址。

更重要的是，移动流量通常被分配在"对称型 NAT（Symmetric NAT）"之后。它的特性是：当手机向内网/外网的不同目标发送数据时，运营商会为每次连接分配不同的公网端口。

- 在家宽（Wi-Fi）环境下，通常是"全锥型"或"限制锥型"NAT，P2P 打洞很容易成功，因为对方总能找到你固定映射的端口。
- 而在移动流量下，由于端口是随机且动态变化的，P2P 打洞的成功率几乎为零（除非依赖中间节点的流量中继转发）。

因此，在目前的网络环境下，想要顺畅地进行陶瓦联机，服务端和客户端应尽量保持在稳定的家宽（Wi-Fi）环境下。如果双端都在移动数据下，或者一端在移动数据下，可能会出现能够开房但无法建立数据连接、或者连接极度不稳定的情况。

## 七、结论

**本次测试是 wow~ 项目的里程碑事件。**

1. wow 集成的陶瓦联机功能，在真实网络环境下验证成功。
2. 跨宽带（3 公里，家宽对家宽）连接稳定，几乎不卡。
3. Windows 服务端 + Android 客户端组合验证成功。
4. 移动网络 P2P 打洞失败是已知限制，不影响 Wi-Fi 场景使用。

## 八、意义

**wow 的"降低开服门槛"目标，在本次测试中得到了实际验证。**

在 IPv4 时代，由于 IP 地址从设计之初就是不足的，不能为每台电脑准备一个 IP，因此诞生了 NAT（Network Address Translation）使同一个路由器下的多个电脑、手机，都共用同一个 IP。（2019 年 11 月 25 日，最后一个主要区域的 IP 注册机构 RIPE NCC 宣布最后的 IPv4 储备池用完）

不过这种技术破坏了端到端通信，使得在线游戏、远程访问等受到影响，有些甚至几乎不可用，只能在局域网内部连接，包括 Minecraft。

许多开服教程文档，都宣称家宽环境不适合开服，但大多数人只有一台摆在家里的电脑，免费的 VPS 也限制诸多，或者稳定性差。

陶瓦（Terracotta）以及其内核（EasyTier）就是一个 P2P 打洞工具，使 Minecraft 联机更加方便，陶瓦在 EasyTier 的基础上专门针对 Minecraft 联机进行了优化。

这一次测试成功说明，家宽开服将是可能的，将是能够稳定运行的。

（注意，即使家宽开服从技术上已经是可行的，但中大型服务器依然不推荐长期家宽开服，因为各个运营商会有可能会判定异常流量。建议使用预生成区块，限制人数，错峰开服）
