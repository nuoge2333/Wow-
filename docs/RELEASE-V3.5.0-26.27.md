## 一、版本号新格式

从本版本起，版本号采用「语义化版本 + 发行包标识」的新格式：

```
V3.5.0-26.27
 └大┘└中┘└小┘ └年┘└序号┘
  主.次.补丁  两位年 十六进制发行序号
```

| 字段 | 含义 | 示例 |
|------|------|------|
| `3.5.0` | 大版本.小版本.补丁更新号（语义化） | 主版本 3、次版本 5、补丁 0 |
| `26` | 发布年份后两位（2026） | 2026 → `26` |
| `27` | 自上传到开源仓库后的第 **39** 个发行包（`27` 为十六进制） | `0x27` = 39 |

> 说明：`27` 是十六进制写法，对应十进制 39。后续发行包递增为 `28`(40)、`29`(41)…`2F`(47)… 以此类推。

配套修改：

- `core/package.json` → `"version": "3.5.0-26.27"`
- `core/src/cli.js` → `.version('3.5.0-26.27', '-V')`
- `update.sh` / `update.bat` → 标签过滤与排序正则已扩展为
  `^v?[0-9]+\.[0-9]+\.[0-9]+(-[0-9]+\.[0-9]+)?$`，
  可正确识别并选中带 `-YY.NN` 后缀的新版本号，自更新不会断裂。

## 二、事件日志系统（核心重构）

新增核心模块 **`core/src/log.js`**，统一记录 wow 本体在运行过程中的关键事件：

- 用户执行了哪些**有效指令**（含 CLI 与 Web 页面），返回是什么，是否运行成功；
- **Minecraft 运行过程中是否报错 / 崩溃**。

### 2.1 设计要点

- **单例模式**：`WowLogger` 类 + 模块级 `logger` 单例，所有模块 `require('./log')` 拿到同一份，避免重复初始化。
- **核心写函数**：`logger.log(level, message)` 为底层写入口，并提供了分级便捷方法：
  `logger.info()` / `logger.impt()` / `logger.warn()` / `logger.erro()`。
- **指令记录**：`logger.command(name, success, detail)` 记录一条指令事件，失败自动标记崩溃（`markCrash()`）。
- **全局兜底**：`installGlobalErrorHook()` 监听 `uncaughtException` / `unhandledRejection`，记入 `ERRO` 并标记崩溃；已在 `cli.js` 启动时安装。
- **环境探测**：文件头自动探测并记录运行系统、系统架构、JAVA 版本、node 版本。

### 2.2 文件命名与滚动

| 文件名 | 说明 |
|--------|------|
| `Wow-[YYYY-MM-DD]-[MIN].log` | 正常日志。`MIN` = 本次 wow 进程当天累计运行分钟数（最小 1） |
| `Wow-[YYYY-MM-DD]-[MIN]-Wrong.log` | 本次运行出现过崩溃/错误时的文件名（追加 `-Wrong`） |

- 每个进程用独立会话文件 `Wow-[日期]-[PID]-active.log` 写入，进程退出时 `rename` 为正式文件名（带运行时长）。
- 跨过 **00:00** 自动另起一个按新日期命名的文件。
- 上次被强杀（SIGKILL 等未正常收尾）遗留的 `-active.log` 会在下次启动时归为崩溃文件清理。
- 同名防覆盖：若目标文件已存在，自动追加 `-2` / `-3` 序号。

日志目录：`Wow/logs/`（项目根目录下的 `logs/`，非 `core/logs/`）。

### 2.3 文件头固定格式

```
Wow～ V3.5.0-26.27
运行系统：linux
系统架构：x64
JAVA版本：20
node版本：22.13.1
```

### 2.4 每行格式（二十四小时制）

```
[HH:MM:SS-信息分级]信息内容
```

信息分级（4 级）：

| 分级 | 含义 |
|------|------|
| `INFO` | 普通运行信息 |
| `IMPT` | 重要运行信息（关键模块、关键操作） |
| `WARN` | 警告（相对危险的操作或迹象） |
| `ERRO` | 错误 / 崩溃 |

## 三、各模块接入点

| 模块 | 接入的日志事件 |
|------|----------------|
| `cli.js` | 安装全局异常钩子；`preAction` 记录「用户执行指令: wow ...」，`postAction` 记录「指令执行完成」 |
| `server.js` | 扫描 MC 输出中的错误特征（`ERROR/SEVERE/FATAL/Exception/Caused by/java.lang` 等）记 `ERRO`；服务器启动/停止/异常退出均记录，非零退出标记崩溃 |
| `web_service.js` | Web 面板启动/停止、Web 页面执行指令及成功/失败（`logger.command`） |
| `installer.js` | 安装服务端核心、下载文件等进度与成败 |
| `jre_manager.js` | JRE 下载成败 |
| `mailer.js` | 邮件发送、崩溃报告准备的成败 |
| `interactive.js` | 交互菜单有效/无效操作记录 |
| `log.js` | 自身全局异常兜底 |
