# 🤖 Android 已知限制说明

> ⚠️ **wow~ 不支持在 Android 上运行。**
> 本文不是故障排除指南，而是一份**结论说明**：经过两个月的实际测试，
> 我们确认 Android 的网络沙箱使 wow~ 的核心功能（开服 + 联机）无法工作，
> 因此撤下所有关于 Android 支持的表述。
>
> Android 设备**可以作为联机客户端**通过陶瓦加入房间（见
> [联机 / 内网穿透](LAN_TERRACOTTA.md)），但不能运行 wow~ 服务端与管理端。

---

## 一、曾经的设想

wow 项目从诞生之初，就一直把"降低 Minecraft 服务器搭建门槛"作为核心理念。我们做了 CLI 和 Web 双模式，做了模板模式的多实例管理，做了陶瓦联机集成，也做了跨平台的支持——Windows、Linux、macOS，一个都不少。

在这条路上，Android 曾经是一个很有吸引力的目标。

理由很简单：手机是大多数人手里唯一能长时间联网、能随身携带、能随时使用的计算设备。如果能在一台 Android 手机上跑 wow，那意味着一个没有电脑、没有 VPS、只有手机的人，也能开一个属于自己的 Minecraft 服务器。这个愿景和我们"让每个人都能开服"的目标完全一致。

于是我们花了大量时间，在 Termux 环境中测试 wow 的可行性。

## 二、测试过程

我们最初的测试是乐观的。

在 Termux 里，我们成功安装了 Node.js，成功下载了服务端核心，成功启动了 Minecraft 服务器。日志里出现了熟悉的 `Done (13.587s)! For help, type "help"`

这能说明 Minecraft 服务端是可以在安卓环境下运行的，但是按照以往经验，作为移动设备，需要进行内网穿透才可连接。

于是我们整合了陶瓦（Terracotta）来进行内网穿透。

当我们尝试让其他设备连接进来时，陶瓦永远显示超时，而服务器端确实好端端的 `host-ok`。

但当我们用另一台设备尝试连接时，超时。我们用陶瓦开房，陶瓦扫描不到端口。我们尝试用 Web 面板从外部访问，同样失败。

更诡异的是，在同一台设备上，用 FCL 启动的 Minecraft 多人游戏尝试连接 `127.0.0.1:25565` 以及陶瓦加入房间时，也超时。

## 三、根因

经过反复排查，我们最终确认了问题的根源：**Android 的网络沙箱**。

Termux 是一个普通 Android 应用，运行在 Android 的网络命名空间中。这个命名空间和标准 Linux 不一样。

在标准 Linux 中，当一个进程监听 `0.0.0.0:25565` 时，同机的其他进程可以通过 `127.0.0.1:25565` 访问它，同网络的其他设备可以通过本机 IP 访问它。这是操作系统的网络栈提供的保证。

但在 Android 上，每个应用都运行在自己的网络命名空间里。Termux 内部监听的端口，只在 Termux 自己的命名空间内可见。其他 App 看不到，其他设备也看不到。

Android 从 6.0 开始逐步收紧非 root 应用的网络能力。到 Android 10 以上，以下操作被限制：

- 绑定低端口（<1024）需要特权
- 监听通配地址（0.0.0.0）在某些 SELinux 策略下被限制为只允许 loopback
- 跨 App 通信需要显式声明或通过 Binder
- VPN 类操作需要 VpnService 权限

（吐槽：保护过度，谷歌又发力了，美其名曰保护用户来卡死我们这群人）

具体来说，有以下几层限制：

1. **跨 App 不可见。** Termux 监听的端口，在另一个 App（比如陶瓦、FCL、浏览器）的命名空间里，是不存在的。即使它们都运行在同一台设备上，也无法通过 `127.0.0.1` 互相访问。
2. **外部设备不可见。** 即使 Android 系统允许端口监听，外部设备也无法访问。因为 Termux 的监听实际上被限制在沙箱内部，系统不会把它暴露到真实的网络接口上。
3. **SELinux 策略。** Android 的 SELinux 策略进一步限制了非特权应用绑定到通配地址的能力。即使你看到 `0.0.0.0:25565` 正在监听，这个"监听"也只是命名空间内部的视角，系统并不会将它真正暴露出去。
4. **非 root 无法绕过。** 这些限制是 Android 平台的设计决定，不是 bug。在非 root 设备上，没有任何方法可以绕过它。

## 四、为什么 proot-distro 不能解决

我们曾经想过一个方案：在 Termux 里用 proot-distro 安装一个完整的 Linux 发行版（比如 Debian），然后在里面跑 wow。

这个方案看起来很诱人，因为 proot-distro 能提供一个几乎完整的 Linux 用户空间。你可以在里面用 apt 安装 Node.js，用 systemd 管理进程，一切看起来都很美好。

但 proot-distro 并没有改变网络命名空间。

proot 是一个用户空间的系统调用模拟器，它不改变进程的网络栈。你在 proot 里跑的 Debian，依然运行在 Termux 的同一个网络命名空间里。你在 proot 里监听的端口，和在 Termux 里监听的端口，在网络层面是一回事。

所以 proot-distro 解决不了这个问题。它改变的是文件系统、用户空间和包管理，但没有改变网络隔离。

## 五、后果

这个限制的后果是严重的。

1. **服务端无法对外提供联机。** 一个无法被外部访问的 Minecraft 服务器，本质上只是一个吃干饭的电老虎。你可以在手机上跑一个服务器，但没有人能连进来。
2. **陶瓦联机失效。** 陶瓦依赖 EasyTier 组网，而 EasyTier 需要真实的网络接口访问。在 Android 沙箱下，陶瓦扫描不到端口，也无法建立 P2P 连接。我们在实际测试中反复遇到 `PingServerRst` 和超时错误，根本原因就在这里。
3. **本地回环跨 App 不可用。** 即使你只想在同一台设备上测试，也无能为力。因为 Termux 的端口在另一个 App 的命名空间里不存在。这意味着你无法在同一台手机上同时运行服务端和客户端。
4. **Web 面板无法被外部访问。** wow 的 Web 面板需要监听端口，供浏览器访问。在 Android 上，这个端口同样被限制在沙箱内，只有 Termux 自己能看到。手机浏览器访问 `http://127.0.0.1:8080` 会直接失败。

## 六、为什么不能修复

我们尝试过所有可能的方案。

- **方案一：更换端口。** 失败。这不是端口被占用的问题，是命名空间隔离的问题。
- **方案二：绑定到局域网 IP。** 失败。Android 不允许非特权应用绑定到真实的网络接口。
- **方案三：使用 VpnService。** 失败。这需要开发一个专门的 Android 应用，并使用 VpnService 权限。它超出了 Termux 和 wow 的能力范围。
- **方案四：使用 Shizuku 或 ADB 提权。** 失败。这需要用户连接电脑或手动配置，门槛极高，且不稳定。更重要的是，它违背了 wow"开箱即用"的设计初衷。
- **方案五：使用 proot-distro。** 失败。如前所述，它不改变网络命名空间。
- **方案六：Root 设备。** 如方案四所说，违背"开箱即用"的设计初衷，也容易好机变砖，这对大量用户来讲都是风险极高的事情。

结论是：**在非 root 的 Android 设备上，Termux 无法对外暴露端口。这是一个平台级的限制，无法通过 wow 的代码修复。**

## 七、决定

基于以上分析，我们决定：**撤下所有关于 Android 支持的表述。**

这个决定意味着：

- README 中的"系统要求"不再包含 Android
- 所有 Android 相关的安装和使用示例从文档中移除
- 本文（原 `TROUBLE_ANDROID(Termux).md` 故障排除）改为"已知限制说明"
- 用户不再被引导去尝试一个不可能成功的方向

我们做出这个决定的理由很简单：**如果一个功能无法在真实环境中工作，那么提供它就是误导用户。** 我们宁愿告诉用户"这件事不行"，也不愿意让他们花几个小时去折腾，最后发现根本跑不通。

## 八、对用户的影响

如果你的设备是 Android，并且你想使用 wow，现在的建议是：

1. **在没有找到确切的解决方案时，没有必要用 Termux 跑服务端。** 因为你无法把服务器开给其他人玩。你只能在本地跑，但它跑不了多好，而且没有任何联机能力。
2. **用手机浏览器访问服务器的 Web 面板。** 如果你已经在 VPS 或家里的电脑上运行了 wow，你可以用手机浏览器直接访问它的 Web 面板。你不需要在手机上安装 wow，也不需要 Termux。你只需要一个能上网的浏览器。
3. **如果你真的想在移动设备上开服，请使用一台真正的 Linux 设备。** 树莓派、旧笔记本、任何一台能装 Linux 的机器，都比 Android 手机更适合做服务器。它们的网络栈没有被限制，端口可以正常暴露，陶瓦可以正常工作。（搞笑的是，当初就是假设你没有…）

我们曾经把 Android 看作一个潜在的平台，但经过验证，我们发现它在当前的技术条件下无法承载 wow 的核心功能。我们把这件事查清楚了，然后把结论告诉了用户。

这比硬撑着"支持 Android"要诚实得多。很多项目为了显得"覆盖面广"，会保留一些名不副实的平台支持。用户看到"支持 Android"就去尝试，然后发现一堆问题，最后失望而归。开发者自己也疲于应付这些无法解决的 bug。

wow 选择了一条更清晰的路：**只支持那些能真正跑起来的平台。Android 不在此列。**

## 十、展望

一个无法连接的服务器是没有任何意义的。

我们不会永远关上门（实则是焊死门，但又不知道哪天突然闪灵劈门，见结尾）。如果未来 Android 平台开放了网络命名空间，或者出现了新的可行方案，我们会重新评估。

但在此之前，Android 上的 wow 不是一个可以使用的工具。它不能作为服务端，不能作为联机端，也不能作为管理端。它只是一个曾经被测试过的可能性，而测试的结果是否定的。

我们把这份说明留在这里，是为了让每一个后来者都不必重复我们的弯路。**如果你在某个地方看到"wow 支持 Android"，请以本文为准。**

wow 会继续在 Linux、Windows 和 macOS 上生长。对于 Android 用户，我们建议用浏览器去管理你的服务器。
